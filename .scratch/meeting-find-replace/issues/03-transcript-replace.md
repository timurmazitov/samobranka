# 03: Замена в транскрипте

**What to build:** В открытой панели поиска пользователь вводит текст в поле «Заменить» и нажимает «Заменить» — текущее совпадение в речевом сегменте заменяется и фокус переходит к следующему совпадению (как в редакторах). «Заменить все (N)» заменяет все совпадения во всех сегментах транскрипта за одно действие, с числом в подписи кнопки, без подтверждения. Правки проходят через существующий путь редактирования текста сегмента (оптимистичное обновление и откат при ошибке уже есть), сохраняются в базе и не теряются после перезагрузки встречи; привычный хинт «саммари устарело — перегенерировать?» продолжает работать после замен.

**Blocked by:** 02 (Панель поиска + навигация по транскрипту).

**Status:** resolved

- [x] «Заменить» меняет активное совпадение в сегменте и переходит к следующему
- [x] «Заменить все» меняет все совпадения во всех сегментах встречи, включая недозагруженные (после догрузки из 02)
- [x] Заменённый текст сохраняется в БД: после перезагрузки встречи правки на месте (проверка через существующую команду обновления текста сегмента)
- [x] Формат отображения сегмента (спикер, таймкод, чистка от слов-паразитов после закрытия панели) не ломается
- [x] Хинт об устаревшем саммари появляется после замен
- [x] Тесты поведения хука: вызовы команды обновления сегмента с правильным текстом для одиночной замены и «заменить все»; частичный сбой не оставляет рассинхрон состояния (откат существующий)

## Comments

- Реализовано в этой ветке: `useFindReplace` получил `replaceText`/`setReplaceText`, `replaceActive`, `replaceAll`, `replaceableCount` и опциональный `onTextEdited` — колбэк существующего пути сохранения строки (в `page-content.tsx` это `handleTranscriptTextEdited` → `setTranscriptText` из `usePaginatedTranscripts` с оптимистичным обновлением, `api_update_transcript_text` и откатом; хинт «саммари устарело» — там же, после успешного сохранения). Замены не имеют собственного пути сохранения. «Заменить» вырезает диапазон совпадения из RAW-текста сегмента, сохраняет через хост-путь и только после успеха переходит к первому совпадению строго после заменённого диапазона (VS Code; повторное совпадение на месте записи не перехватывает фокус, цикл доходит до него через ↓). «Заменить все» планирует замену по всем сегментам один раз (несколько совпадений в сегменте — один вызов команды) и сохраняет сегменты последовательно; отказ сегмента откатывает его существующим откатом, остальные сохраняются, список совпадений пересчитывается из фактического текста; частичный сбой выбрасывает `ReplaceAllPartialFailureError` (только число отказов — без приватного текста), панель показывает переводной тост (`findReplace.replaceAllFailed*`), одиночный отказ — существующие строки `transcript.updateTextFailed*`. Пустое поле «Заменить» удаляет совпадение; no-op замена не пишет, но переходит дальше.
- Тесты: `bun test tests/hooks/find-replace.test.tsx` — 22 pass (одиночная замена с проверкой аргументов `api_update_transcript_text`, переход к следующему, повторное совпадение после замены, «заменить все» — по одному вызову на изменённый сегмент, пустое поле = удаление, нет совпадений — нет вызовов, откат одиночной и частичной замены — состояние следует за фактическим текстом, возврат фокуса на откаченное совпадение); `tests/components/meeting-details-summary-hint.test.tsx` — хинт появляется после замен через реальную панель (один dedup-тост с фиксированным id на всю пачку); затронутые файлы (`paginated-transcripts`, `transcript-text-edit`, `transcript-edit-summary-hint`, `i18n-parity`) — pass; полный `bun test tests/` — 696 pass / 10 fail, тот же baseline mock-isolation, новых падений нет. `tsc --noEmit` — без новых ошибок (единственная — предсуществующая в `stage-transcribe-native.test.ts`).
