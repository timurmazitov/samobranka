# 02: Режим выделения с массовым удалением

**What to build:** В группе кнопок панели транскрипта появляется кнопка «Выделение». По нажатию у строк транскрипта появляются чекбоксы, пользователь отмечает несколько речевых сегментов и удаляет их за один раз кнопкой «Удалить (N)» с подтверждением «Удалить N сегментов?» для N>1 (одиночное удаление, из 01, подтверждения не требует). Удаление идёт одной батч-командой (одна транзакция), после массового удаления текущая страница перезагружается, чтобы offset-пагинация не пропустила строки. Выделение эфемерное: сбрасывается при выходе из режима и при смене встречи, не переживает перезапуск.

**Blocked by:** 01 (Одиночное удаление речевого сегмента — даёт батч-команду, метод хука и гейты).

**Status:** resolved

- [x] Кнопка «Выделение» в панели транскрипта включает/выключает режим; в режиме у строк отображаются чекбоксы.
- [x] Панель действий режима: «Удалить (N)» со счётчиком выбранных; подтверждение «Удалить N сегментов?» только при N>1.
- [x] Массовое удаление выполняется одной батч-командой; при ошибке — откат всех выбранных сегментов.
- [x] После массового удаления — refetch текущей страницы; `totalCount`/`has_more` остаются честными, следующая страница не пропускает строки.
- [x] Выделение не переживает выход из режима и смену встречи; не персистится между перезапусками.
- [x] Гейты режима совпадают с гейтами одиночного удаления (запись/диаризация/ретранскрипция блокируют).
- [x] Тесты: поведение выделения (выбор, счётчик), подтверждение при N>1 и его отсутствие при N=1, откат при ошибке батч-команды, изоляция выделения при смене встречи.

## Comments

Реализация (тикеты 02):

- **Хук пагинации** (`usePaginatedTranscripts.ts`): у `deleteTranscripts(ids)` появился второй аргумент `{ refetchWindow?: boolean }`. После успешной батч-команды (только для bulk) окно перезагружается из нуля (`loadTranscriptsAtOffset(requestId, 0, false, windowSize)`), где `windowSize = max(offsetRef.current, PAGE_SIZE)` — это пост-удаления счётчик загруженных строк (offsetRef уже декрементирован). Окно всегда начинается с начала транскрипта (append-only), поэтому перезагрузка просит ровно `[0, loadedCount)` и **никогда** не усечёт мультистраничный список до дефолтных 100. При `windowSize` ≤ страницы удалятся все загруженные строки частично загруженной встречи — подтягиваем хвост, иначе пустой список с `has_more` оживить нечем (scroll-триггер рендерится только при `segments.length > 0`). Ошибка перезагрузки окна оставляет честные оптимистичные счётчики (само удаление уже прошло). Одиночное удаление (`refetchWindow` не передан) окно не перезагружает — дешёвый путь корзинки сохранён.
- **Состояние выделения** — новый хук `hooks/meeting-details/useTranscriptSelection.ts` (эфемерный набор id, как состояние find-панели у `useFindReplace`). Владелец — `page-content` (вью общей с живой страницей). `enterSelection` всегда стартует с пустого набора; `exitSelection` чистит id; смена `meetingId` сбрасывает и режим, и id (эффект по meetingIdRef); unmount чистит состояние вместе с владельцем (page.tsx `key={meetingId}`). Для тикета 04 оставлены отдельные `enterSelection`/`exitSelection` (двусторонняя взаимоисключаемость: Find/pencil закроют режим через `exitSelection`, вход в выделение закроет редактор/панель).
- **Кнопка «Выделение»** (`TranscriptButtonGroup.tsx`): lucide `SquareCheck`, следующим за Find, `variant=secondary` при активном режиме, `disabled = isRecording || isDiarizing || isRetranscribing`, `aria-pressed`. Кнопка появляется только когда передан `onToggleSelection` (живая страница не получает). Группа **начала получать** `isRecording`/`isDiarizing`/`isRetranscribing` пропсами — `TranscriptPanel` их теперь пробрасывает (раньше не получала).
- **Чекбоксы и панель действий** (`VirtualizedTranscriptView.tsx`): чекбокс — первым ребёнком `flex items-start gap-2` строки (текст не сдвигается), только при `selectionMode && allowDelete && !isStreaming && onToggleSelected`; проброшен в **обе** ветви рендера. Липкая панель действий: «Удалить (N)» (`variant=destructive`, `disabled` при N=0/в полёте). Подтверждение при N>1 через существующий `ConfirmationModal` («Удалить N сегментов?»), при N=1 — мгновенно (спека: одиночное не подтверждает). Ошибка батча — только переводные тосты `deleteSegmentFailed{,Description}` (приватность как у одиночного), сырая ошибка в `console.error`.
- **Провязка страницы**: `page.tsx` — `handleSegmentsBulkDeleted = deleteTranscripts(ids, { refetchWindow: true })` + один `loadMeetingSpeakers()` после успеха (read DB; reconcile в команде уже убрал мёртвые назначения). `page-content.tsx` — владеет `useTranscriptSelection`, `handleSegmentsBulkDeleted` чистит id **только после успеха** (отказ сохраняет выделение для повтора после отката). Подсказка «саммари устарело» для bulk НЕ добавлена — это решение тикета 05 (место указано комментарием в `handleSegmentsBulkDeleted`).
- **Каталоги**: ключи `transcript.selectModeTooltip/selectSegmentAria/deleteSelected/deleteSelectedTooltip/deleteConfirm_{one,few,many,other}` в en+ru («речевой сегмент», без «реплика»); i18n-parity и i18n-usage зелёные.

**Решения для тикетов 03–05:**
- **03 (выделение по спикеру/всё видимое/Ctrl-Shift/Delete/Esc):** используйте `setSelectedIds(ids)` хука выделения (дедуплицирует). «Выделить всё видимое» = все **загруженные** id (`segments.map(s => s.id)`), повторное нажатие снимает; «по спикеру» фильтруйте загруженные сегменты по `segment.speaker === label` (не по `meetingSpeakers[].segment_count` — это вся встреча). Клавиши — расширяйте **единственный** document-слушатель в `page-content.tsx:~257`: Escape для режима обязан вызвать `event.preventDefault()` (иначе закроет find-панель), Delete → удаление выбранного. Выход из режима по Esc — `exitSelection()`.
- **04 (взаимоисключение режимов):** состояние выделения ищет `exitSelection`/`enterSelection` уже готовыми. Вход в выделение → `closePanel()` (find) + флап пропа-гейта, закрывающего открытый inline-редактор через эффект `allowTextEdit` (`VirtualizedTranscriptView.tsx:~321`, сохраняет черновик). Открытие Find (включая хоткеи Ctrl+F/H в слушателе страницы) и клик карандаша → `exitSelection()` + чистка id. Карандаш: рядом с `onClick` в строке (~`setIsEditing(true)`).
- **05 (подсказка «саммари устарело» после bulk):** вызовите `notifySummaryStale()` ровно **один раз** после успеха `onSegmentsBulkDeleted` в `page-content.handleSegmentsBulkDeleted` (комментарий на месте) — та же id-дедуплицированная sonner-цепочка, что у одиночного удаления; не заводите новое событие.
