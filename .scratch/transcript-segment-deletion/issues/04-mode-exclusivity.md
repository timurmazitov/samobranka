# 04: Взаимоисключение режимов выделения, редактирования и поиска/замены

**What to build:** Над строками транскрипта одновременно может работать только один режим. Вход в режим выделения закрывает открытое построчное редактирование текста (карандаш) и панель поиска/замены. Симметрично: попытка открыть редактирование строки или поиск/замену из режима выделения выходит из выделения. Это исключает конфликты, когда два bulk-режима (выделение-удаление и «найти и заменить») правят одни и те же строки.

**Blocked by:** 02 (Режим выделения с массовым удалением).

**Status:** resolved

- [x] Вход в выделение закрывает открытое inline-редактирование строки (без потери несохранённого текста — поведение как при существующем выходе из редактирования).
- [x] Вход в выделение закрывает панель поиска/замены.
- [x] Открытие поиска/замены или начало редактирования строки выходит из режима выделения со сбросом выделенного.
- [x] Нет состояния, в котором чекбоксы выделения и редактирование/поиск активны одновременно.
- [x] Тесты на конфликты режимов в обе стороны.

## Comments

Реализация (тикеты 04):

- **Строка** (`VirtualizedTranscriptView.tsx`): эффект на переходе `selectionMode` в true — зеркало эффекта `allowTextEdit` (паттерн диаризации): открытый редактор под входящим режимом отдаёт черновик тем же host-путём сохранения (однократно, без цикла) и закрывается; нетронутый черновик закрывается без команды. Карандаш перед открытием редактора вызывает новый проп `onExitSelection` (хост выходит из режима и чистит id), затем открывает редактор локально — тот же односторонний триггер, что и у панели. `onExitSelection` проброшен в **обе** ветви рендера; без хоста (живая страница) проп отсутствует и карандаш не меняется.
- **Панель** (`MeetingDetails/TranscriptPanel.tsx`): новый прозрачный проп `onExitSelection` → во вью.
- **Страница** (`page-content.tsx`): `toggleSelectionMode` = `toggleSelection()` + `closePanel()` (вход в выделение разоружает find; выход — no-op); `openFindPanel(options)` = `exitSelection()` + `openPanel(options)` — единственный вход в панель для обеих кнопок Find (транскрипт и саммари) **и** хоткеев Ctrl+F/H в document-слушателе, поэтому «открыли find из выделения» симметрично всегда выходит из режима со сбросом id. Esc-семантика не тронута (режим по Esc — тикет 03).
- **Каталогов нет** — новых строк не добавлено (i18n-parity/i18n-usage зелёные).
- **Тесты**: `tests/components/transcript-mode-exclusivity.test.tsx` (5) — флеш черновика при входе в режим поверх открытого редактора (в т.ч. нетронутый черновик), карандаш из режима зовёт `onExitSelection` и открывает редактор, карандаш без хоста неизменен; `tests/components/meeting-details-mode-exclusivity.test.tsx` (8) — page-level обе стороны: вход в режим закрывает панель, кнопка Find (транскрипт/саммари) и Ctrl+F/Ctrl+H выходят из режима с чисткой id (панель реально открыта), `onExitSelection` доходит до панели.
