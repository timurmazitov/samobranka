# Spec: Удаление речевых сегментов из транскрипта встречи

Status: ready-for-agent

## Problem Statement

При прослушивании/чтении транскрипта встречи пользователь видит мусор: случайные шумы, оговорки, сегменты не тех спикеров, обрывки фраз, попавшие в транскрипцию. Сейчас транскрипт можно только править построчно (текст, спикер) или пересоздать целиком через ретранскрипцию. Нельзя убрать отдельные ненужные речевые сегменты — ни по одному, ни пачкой.

## Solution

В карточке завершённой встречи пользователь может удалить один или несколько речевых сегментов из транскрипта:

- одиночное удаление — иконка корзины при наведении на строку, применяется сразу;
- массовое удаление — режим «Выделение» с чекбоксами у строк, выделение нескольких сегментов (вручную, Ctrl/Shift-диапазонами, «выделить всё видимое», «выделить по спикеру») и удаление за один раз с подтверждением.

Удаляется только запись транскрипта; аудиофайл встречи не меняется. Удалённые сегменты исчезают из просмотра, копирования, экспорта, поиска и из входного текста при перегенерации саммари.

## User Stories

1. Как слушатель встречи, я хочу удалить один речевой сегмент с мусорным текстом, чтобы транскрипт было легче читать.
2. Как слушатель встречи, я хочу удалить сегмент одним кликом (иконка корзины при наведении без лишних диалогов), чтобы чистка была быстрой.
3. Как слушатель встречи, я хочу войти в режим выделения и отметить чекбоксами несколько сегментов, чтобы удалить их за один раз.
4. Как слушатель встречи, я хочу удалять сегменты Ctrl/Shift-кликом по строкам (диапазоны), чтобы не кликать чекбоксы по одному на длинных встречах.
5. Как слушатель встречи, я хочу кнопку «Выделить всё видимое», чтобы быстро очистить весь загруженный транскрипт целиком.
6. Как слушатель встречи, я хочу возможность выделить все сегменты одного спикера, чтобы очистить речь конкретного человека (например, ведущего с микрофоном-эхом).
7. Как слушатель встречи, я хочу видеть счётчик выбранных сегментов на кнопке удаления («Удалить (7)»), чтобы понимать масштаб операции до подтверждения.
8. Как слушатель встречи, я хочу подтверждение при массовом удалении («Удалить N сегментов?»), чтобы не потерять фрагменты случайно.
9. Как слушатель встречи, я хочу, чтобы одиночное удаление не требовало подтверждения, чтобы мелкие правки оставались мгновенными.
10. Как слушатель встречи, я хочу кнопку Delete для удаления выбранного и Esc для выхода из режима выделения, чтобы чистка работала с клавиатуры.
11. Как слушатель встречи, я хочу, чтобы уцелевшие сегменты сохранили свои таймкоды, чтобы текст соответствовал реальному времени в записи.
12. Как слушатель встречи, я хочу, чтобы панель спикеров обновлялась после удаления (спикер без сегментов исчезает), чтобы список спикеров не врал.
13. Как слушатель встречи, я хочу, чтобы саммари оставалось доступным после удаления, а предложение перегенерации подсказывало, что оно устарело, чтобы я сам решал, когда пересобиирать.
14. Как слушатель встречи, я хочу, чтобы скопированный/экспортированный транскрипт не содержал удалённые сегменты, чтобы делимый артефакт был чистым.
15. Как слушатель встречи, я хочу перегенерировать саммари после очистки, чтобы оно строилось только по оставшимся сегментам.
16. Как слушатель встречи, я хочу, чтобы удалённые сегменты исчезали из результатов поиска по транскриптам, чтобы поиск не находил несуществующий текст.
17. Как слушатель встречи, я хочу, чтобы удаление сегментов не влияло на аудиофайл, чтобы запись оставалась полной для переслушивания.
18. Как слушатель встречи, я хочу, чтобы удаление не склеивало соседние сегменты одного спикера, чтобы не терять границу между разными высказываниями.
19. Как слушатель встречи, я хочу, чтобы удаление всех сегментов было возможным (пустой транскрипт), чтобы можно было очистить встречу целиком.
20. Как пользователь, я хочу, чтобы выделение сбрасывалось при выходе из режима и при смене встречи, чтобы не удалять сегменты не той встречи.
21. Как пользователь, я хочу, чтобы режим выделения был недоступен во время записи, диаризации и ретранскрипции, чтобы не конфликтовать с процессами, которые меняют транскрипт.
22. Как пользователь, я хочу, чтобы вход в режим выделения закрывал открытое построчное редактирование и панель поиска/замены, чтобы над строками не было двух конкурирующих режимов.
23. Как слушатель встречи, я хочу, чтобы при ошибке удаления сегменты вернулись на место (откат), чтобы интерфейс не расходился с базой.
24. Как слушатель встречи, я хочу, чтобы при частичном несовпадении id (чужая/удалённая строка) удаление не выполнялось вообще, чтобы операция была предсказуемой.
25. Как слушатель встречи, я хочу, чтобы ошибка удаления не показывала содержимое транскрипта, чтобы приватные фрагменты встреч не попадали в логи и сообщения.

## Implementation Decisions

- **Область**: только карточка завершённой встречи. Живой транскрипт во время записи остаётся read-only.
- **Жёсткое удаление** строк из таблицы речевых сегментов (`transcripts`, PK — текстовый id сегмента). Никаких soft-delete флагов и undo. Миграция схемы не нужна.
- **Аудио не затрагивается**; зеркало `transcripts.json` в папке встречи не синхронизируется (прецедент текстовых правок; ретранскрипция и так пересобирает транскрипт из аудио и может вернуть удалённые сегменты — это принято осознанно).
- **Таймкоды**: уцелевшие сегменты сохраняют оригинальные `audio_start_time`/`audio_end_time`; без перенумерации, без сдвига, без склейки соседних сегментов одного спикера. Дыры во времени допустимы.
- **Новая батч-команда Tauri** (`api_delete_transcripts(meeting_id, ids)`): одна транзакция — проверка принадлежности id встрече, `DELETE` по id, обновление `meetings.updated_at`, однократный вызов reconcile назначений спикеров (удаляет метки спикеров, у которых не осталось сегментов, и сирот справочника людей; уважать names-reset событие). Ошибки — в духе существующего репозиторного errors-типа: unknown id → ошибка «не найдено», пустой текст недоступен (удаление его не касается); `Display` ошибок не содержит содержимое встреч.
- **Фронтенд-состояние**: расширение хука пагинированных сегментов (`usePaginatedTranscripts`) методом удаления — оптимистичное удаление из локального списка, декремент `totalCount`/смещения, при неуспехе — откат. После bulk-удаления — коррекция текущей страницы (refetch), чтобы offset-пагинация не пропускала строки.
- **Выделение** — эфемерное состояние компонента транскрипта (набор id): сброс при выходе из режима и при смене встречи; не персистится.
- **UI-поверхности**: hover-иконка корзины в строке сегмента (рядом с карандашом редактирования) в виртуализированном представлении транскрипта; кнопка «Выделение» в группе кнопок панели транскрипта (рядом с Copy/Export/Find); панель действий режима выделения: «Выделить всё видимое», «Выделить по спикеру», «Удалить (N)», подтверждение при N>1, Delete/Esc.
- **Режимы взаимоисключающие**: вход в выделение закрывает inline-редактирование строки и панель Find/Replace; гейты доступности — те же, что у редактирования (`!isRecording && !isDiarizing`), плюс блокировка во время ретранскрипции.
- **Саммари**: уже сгенерированное не пересобирается автоматически; переиспользуется существующий хук подсказки «саммари устарело / Regenerate», которым сопровождается правка текста. Отпечаток english-кэша сам разойдётся при перегенерации.
- **Производные представления** (копирование, экспорт, поиск, панель спикеров, входной текст саммари) читают базу — удалённые сегменты исчезают в них автоматически, отдельной логики нет.
- **Терминология**: UI-тексты и код — по GLOSSARY.md («речевой сегмент», «спикер», «справочник людей»; avoid «реплика»).
- **Пустой транскрипт после удаления всех сегментов** — валидное состояние без спец-предупреждений.

## Testing Decisions

- Тестируем внешнее поведение, не детали реализации: что пользователь видит до/после удаления, откат при ошибке, актуальность счётчиков и панелей.
- **Нативный seam — репозиторий сегментов** (in-memory SQLite с настоящими миграциями, существующий паттерн `migrated_pool()`): батч-удаление своих id; отказ при id чужой встречи/несуществующем id; отсутствие частичного удаления при ошибке (атомарность); bump `meetings.updated_at`; reconcile скрывает спикера без сегментов и не трогает остальных.
- **Фронтенд seam — хук пагинации сегментов** (bun-тесты хуков, паттерн существующих тестов `paginated-transcripts.test.tsx`): оптимистичное удаление и откат при reject команды; декремент `totalCount` и честность `has_more`; refetch страницы после bulk; сброс/изоляция выделения (смена встречи, выход из режима).
- **Компонентные тесты строки/режима** (паттерн тестов построчного редактирования): появление чекбоксов в режиме, одиночное удаление без подтверждения, подтверждение при N>1, недоступность при записи/диаризации.
- Приоритет — поведение на двух существующих seams; новых seams не заводим.

## Out of Scope

- Undo/мягкое удаление/восстановление сегментов.
- Вырезание соответствующих фрагментов из аудиофайла.
- Склейка соседних сегментов одного спикера после удаления.
- Удаление/редактирование сегментов во время живой записи.
- Синхронизация `transcripts.json` в папке встречи с удалением.
- Персистентность выделения между перезапусками.
- Редактирование порядка сегментов, перенумерация таймкодов.
- Подсказка «восстановить удалённое» / корзина.

## Further Notes

- Известное принятое последствие: будущая ретранскрипция пересобирает весь транскрипт из аудио и вернёт удалённые сегменты — осознанно принято на этапе обсуждения.
- Offset-пагинация + bulk-удаление — источник потенциально пропущенных строк на следующей странице; решается refetch текущей страницы (прецедент: полное обновление после ретранскрипции).
- Ссылки на репозитории/компоненты намеренно даны ролями (репозиторий сегментов, хук пагинации, виртуализированное представление транскрипта, группа кнопок панели), чтобы spec не устаревал при переименованиях; актуальные имена — в коде (`database/repositories/transcript.rs`, `hooks/usePaginatedTranscripts.ts`, `components/VirtualizedTranscriptView.tsx`, `components/MeetingDetails/TranscriptButtonGroup.tsx`).
