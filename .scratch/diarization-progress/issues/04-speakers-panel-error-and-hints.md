# 04: Панель Speakers — честная ошибка, «Повторить» и подсказки недоступности

**What to build:** Индикатор диаризации в панели Speakers честно умирает: при неудачном проходе вместо испарения показывается «Диаризация не удалась: <причина>» и кнопка «Повторить» (повторный запуск того же прохода); тост об ошибке сохраняется. Когда диаризация не может запуститься, панель Speakers явно объясняет почему: при отсутствии модели — подсказка скачать модель в настройках, при отсутствии рантайма audio.cpp — соответствующее объяснение. Индикатор корректно отражает и автоматический проход (после импорта/ретранскрипции), а не только ручной запуск.

**Blocked by:** 02 — Трейсер: событие `diarization-progress` и общий стейт прохода.

**Status:** ready-for-human

- [x] При `Failed` индикатор переходит в error-состояние с причиной и кнопкой «Повторить»; повторный запуск работает; тост сохраняется
- [x] При отсутствии модели/рантайма в панели Speakers видна явная подсказка вместо отсутствующего индикатора
- [x] Автоматический проход после импорта виден в панели Speakers так же, как ручной

## Comments

Имплементация (тикент 04), ветка `feat/dp-04`:

- Error-переход живёт в общем редьюсере стейта прохода (`frontend/src/lib/diarization.ts`):
  `DiarizationPassState` получил `phase: 'running' | 'failed'`, `error: string | null`
  и nullable `stage`; новый чистый `applyDiarizationFailure` переводит терминал
  `diarization-unavailable` со статусом `failed` в error-состояние (причина — `reason`,
  при его отсутствии `message`; ни того ни другого — `error: null`). Только `failed`:
  конфигурационные статусы и чужая встреча не трогают состояние; терминалы успеха
  (`transcript-updated`, `speaker-names-reset`) и не-`failed` payload на канале
  unavailable гасят индикатор, как раньше. `DiarizationPassStore.handle` вызывает
  редьюсер на этом терминале; первый же стадийный эмит повторного прохода заменяет
  error на спиннер.
- Панель (`SpeakersPanel.tsx`): error-блок «Диаризация не удалась: <причина>»
  (`t('speakers.passFailed')` / `passFailedNoReason`) + кнопка «Повторить»
  (`t('speakers.retry')`), которая зовёт существующий `handleDiarize` (тот же
  клиент ручной команды); guard блокирует запуск только при `phase === 'running'`,
  поэтому повтор из error-состояния проходит. Toast-путь не тронут: тосты
  автоматических проходов по-прежнему дают слушатели `diarization-unavailable`
  в импорте/ретранскрипции (проверено тестами `notify` не дублируется).
  Индикатор/ошибка рендерятся над всеми ветками панели — видны и при уже
  существующих спикерах (ретранскрипция/повторный проход).
- Ручной запуск: при `status === 'failed'` результат команды остаётся собственником
  error-состояния (терминал эмитится тем же проходом) — `finally` не стирает его;
  успех и не-терминальные отказы чистят стейт, как раньше.
- Подсказки недоступности: при `hasDiarizationModel === false` панель показывает
  явную строку `DIARIZATION_NO_MODEL_MESSAGE` (зеркало нативного текста, тот же,
  что при ручном отказе) вместо прежнего общего хинта; для рантайма добавлен
  проксированный через seam `modelClient.getDiagnostics` (опционально) probe
  `audiocpp_diagnostics`: при `available: false` — `DIARIZATION_NO_RUNTIME_MESSAGE`
  и disabled кнопки с этим же текстом в title. Приоритет: модель важнее рантайма
  (первый actionable отказ). Неизвестный каталог/рантайм (`null`) ничего не блокирует.
- Автопроход после импорта/ретранскрипции: тест гоняет все пять стадий через чистые
  эмиты без ручного запуска — индикатор и disabled-кнопка ведут себя как при ручном.
- i18n: новые ключи `speakers.passFailed` (интерполяция `{{reason}}`),
  `speakers.passFailedNoReason`, `speakers.retry` — в обоих каталогах.
- Проверено: `bun test` новых/затронутых файлов зелёные (42 pass pass-state+panel,
  67 pass speakers-panel/live-diarization/i18n-гарды, 49 pass остальные диаризационные
  сюиты); полный `bun test` — 496 pass / 9 fail = ровно baseline mock-isolation
  падений; `tsc --noEmit` без новых ошибок (1 предсуществующая в
  `stage-transcribe-native.test.ts`). Бэкенд не тронут — `cargo test` не запускался.
  Ручная проверка в Tauri-приложении не выполнялась (GUI не запускался) — пункт
  остаётся за тикетом.
